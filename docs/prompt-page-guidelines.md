# 프롬프트 페이지 유형 가이드라인

이 문서는 **AI Learning Studio** 프로젝트에서 사용하는 5가지 공식 승인 페이지 유형과 세부 구현 규칙을 다룹니다.

---

## 1. 프롬프트 페이지 유형 개요

프로젝트에서는 사용자 승인 없이 새 페이지 유형을 추가하지 않으며, 승인된 공식 렌더러 유형은 다음과 같습니다.

1. `landing` (홈 랜딩)
2. `static-prompt` (완성형 프롬프트 및 인라인 콤보박스)
3. `prompt-builder` (입력 폼 기반 동적 조합 빌더)
4. `markdown-prompt` (정형화된 마크다운 가이드/지침서)
5. `practice-timeline` (단계별 실습 타임라인 - 미사용 예약)

---

## 2. 프롬프트 본질 및 미리보기 노출 철칙 (Source of Truth)

모든 프롬프트 UI는 다음 2가지 본질적 구분에 따라 엄격히 동작하며, 불필요한 미리보기 상자를 남발하지 않습니다.

1. **그냥 프롬프트 (Standard Static Prompt)**:
   - **본질**: 별도 사용자 조건 설정 없이, 완성된 최적의 프롬프트를 있는 그대로 읽고 직관적으로 복사하는 프롬프트.
   - **UI 규칙**: 불필요한 미리보기 박스(`✨ 완성된 프롬프트`)를 **절대 렌더링하지 않으며**, 본문 카드 하단 `footer`에 바로 **[프롬프트 복사]** 버튼을 직접 배치함.

2. **설정에서 그 값을 받아서 바로 반영하는 프롬프트 (Configurable Dynamic Prompt)**:
   - **본질**: 사용자가 폼/드롭다운 옵션을 고르거나 텍스트 조건(인라인 태그 칩 등)을 입력하면, 그 변경된 값을 실시간으로 받아 바로 조합해 주는 프롬프트.
   - **UI 규칙**: 오직 조절 태그나 빌더 필드가 존재하는 경우에만 하단에 **`✨ 완성된 프롬프트 (실시간 미리보기)` 독립 카드**가 동적으로 노출되어 실시간 조립 결과와 복사 기능을 제공함.

---

## 3. 유형별 명세 및 규칙

### A. `static-prompt`
- **목적**: 완성된 최적의 프롬프트를 바로 확인하고 복사할 수 있는 정적 페이지.
- **특징 및 인라인 스마트 콤보박스 규칙**:
  - 프롬프트 본문 텍스트 내 `[ 선택지1 / 선택지2 / 선택지3 ]` 포맷 사용 시, 브라우저가 자동 파싱하여 **드롭다운 선택과 직접 텍스트 입력(자유 타이핑)을 동시에 지원하는 인라인 스마트 태그 칩**으로 자동 전환됨.
  - 단, 대괄호 묶음이 단독으로 한 줄을 차지하면 섹션 헤더(예: `[작성 지침]`)로 오인되어 칩으로 변환되지 않으므로, 레이블과 같은 줄에 두거나(`- 목적: [선택지]`) **자유 텍스트 입력 필드의 경우 반드시 양쪽에 따옴표를 추가(`"[텍스트 입력]"`)**하여 옵션 칩으로 정상 제공되게 해야 함.
  - 사용자가 선택하거나 타이핑한 커스텀 값이 반영된 정돈된 최종 프롬프트가 **[프롬프트 복사]** 버튼을 통해 클립보드에 원형 복사됨.
  - 복사 버튼(`CopyButton`) 및 외부 AI 열기(`ExternalAiActions`) 기능 제공.

### B. `prompt-builder`
- **목적**: 사용자가 입력한 조건/선택지를 조합하여 상황 맞춤형 프롬프트를 즉시 조립하는 페이지.
- **흐름**:
  ```text
  입력·선택 → 프롬프트 만들기 → 결과 확인 → 복사 → ChatGPT/Gemini 열기
  ```
- **핵심 규칙**:
  - **외부 AI API를 직접 호출하지 않습니다.** (클라이언트 사이드 문자열 템플릿 조합 방식 사용)
  - 빈 선택 필드는 결과 조합 시 자동으로 생략합니다.
  - 사용자가 입력하지 않은 사실을 임의로 지어내지 않습니다(환각 금지).
  - 결과물은 사용자가 직접 수정 및 복사할 수 있어야 합니다.
  - 외부 AI 연결 시 "자동 입력되는 것이 아니며, 복사 후 붙여넣어야 함"을 명확히 안내합니다.

### C. `practice-timeline`
- **목적**: 단계별로 AI 프롬프트 활용법을 실습하며 변화를 관찰하는 세로형 타임라인 페이지.
- **특징**:
  - 세로형 연속 흐름 페이지 (Wizard, Tab, Slide UI 형태 사용 금지).
  - JSON 배열 데이터를 기반으로 정적 HTML 생성.
- **단계별 포함 요소**:
  - 단계 제목, 학습 포인트, 프롬프트, 복사 버튼, 설명, 변경점(무엇이 달라졌는지), 예상 결과.
  - 마지막 최종 완성 프롬프트는 시각적으로 명확히 강조 표시.

### D. `markdown-prompt`
- **목적**: 마크다운 원문(Raw Text)을 변환 없이 순수하게 노출하고 복사할 수 있도록 제공하는 페이지.
- **특징**:
  - `static-prompt`와 동일한 UI 구조를 재사용하나, 내부 텍스트를 HTML 칩(Chip)으로 파싱하지 않습니다.
  - 마크다운 기호(`#`, `**`, `[옵션]`)가 렌더링되지 않고 있는 그대로 `<pre><code>` 블록에 노출됩니다.
  - 복사 버튼 클릭 시 평문 상태의 텍스트가 클립보드에 그대로 복사됩니다.

## 4. 프롬프트 마크다운 작성 및 서식 규칙

- **볼드(`**`) 서식 최소화 및 평문화 (의무)**:
  - 프롬프트 마크다운(`.md`) 작성 및 수정 시 대분류 헤더(`###`) 등 구조상 필수적인 경우가 아니면 옵션명, 목록 항목, 본문 설명, 프롬프트 내부 지침에 불필요한 `**` (볼드 마크다운)을 추가하지 않습니다.
  - 옵션 목록은 `- **옵션명**:` 대신 `- 옵션명:` 형태의 깔끔한 단일 라인(Flat) 구조를 표준으로 준수합니다.
- **인라인 콤보박스 및 자유 텍스트 따옴표 칩 규칙 (의무)**:
  - `[여기에 글 붙여넣기]` 같은 자유 텍스트 입력 옵션 칩이 단독으로 한 줄을 차지할 경우 파싱 엔진에 의해 '섹션 헤더'로 오인되어 무시됩니다.
  - 따라서 옵션 칩이 정상적으로 나타나게 하려면 **반드시 `"[여기에 글 붙여넣기]"`와 같이 양쪽에 따옴표(`" "`)를 감싸서 옵션으로 제공**해야 합니다.
- **옵션 드롭다운 내 `"[자유 입력]"` 생성 금지 (의무)**:
  - 웹 UI의 모든 인라인 콤보박스 드롭다운 칩에는 사용자가 임의로 타이핑하여 값을 변경할 수 있는 '직접 입력' 기능이 자체 내장되어 있습니다.
  - 따라서 프롬프트 선택 옵션 작성 시 선택지 끝에 `"[자유 입력]"`, `"[직접 입력]"` 등을 관습적으로 추가하는 것을 엄격히 금지합니다.
  - 모든 드롭다운은 완성도 높고 검증된 구체적 프리셋들로만 명확히 구성해야 하며, 사용자가 직접 문장을 작성해야 하는 단독 텍스트 입력 필드(예: `문장: "[표현할 문장]"`)가 명시적으로 필요한 경우가 아니라면 일반 드롭다운 옵션 목록 끝에 자유 입력 칩을 임의로 생성하지 않습니다.
- **AI 해석 최적화 마크다운 포맷팅 규칙**:
  - 옵션 드롭다운 영역 및 각 하위 지시 목록의 마커는 항상 `- `로 통일합니다.
  - 각 대분류 지침(`###` 헤더)과 설명 문장 사이에는 정확히 1줄의 공백 라인만 배치하여 단락 경계를 명확히 분리합니다.
  - 옵션 설명 매핑부는 `* **옵션명** \n 설명`과 같은 개행 구조를 피하고, `- 옵션명: 설명` 형태의 단일 라인(Flat) 구조로 정리합니다.
- **콤보박스 기본값(1순위) 설계 규칙**:
  - 구도/비율: 원본 파손율이 가장 적은 `원본 사진 비율 유지` 또는 `사진 구도 그대로`를 무조건 1순위(기본값)로 배치합니다.
  - 화풍/색감: 해당 프롬프트의 특징을 가장 강력하게 나타내는 대표 옵션을 1순위로 배치합니다.

## 5. 데이터 무결성 및 메타데이터 검증 규칙

- **프롬프트 설명문(Description) 동기화 규칙 (자동 검증)**:
  - 프롬프트 마크다운(`.md`) 파일 내부의 `description`이나 제목을 수정할 때에는 아래 2개 JSON 데이터 파일도 완전히 일치하도록 함께 수정해야 합니다. 불일치 시 빌드가 자동으로 실패합니다 (`core/data_consistency.py`).
    - `data/page-registry.json`
    - `data/navigation.json`
- **수정 전 Git 히스토리 대조 선조사 규칙**:
  - 지침 파일을 정돈하거나 프롬프트를 수정하기 전에 무조건 최근 3개 커밋 내역(`git log -p -n 3`)을 조회하여 사용자의 수동 개입/수정 이력을 100% 선조사하고, 기존에 임의 기입된 커스텀 메타데이터(예: 다중 `preview` 이미지나 수동 `source` 정보 등)를 덮어쓰지 않고 온전히 보존해야 합니다.
- **메타데이터(preview/source) 적합성 검증 규칙**:
  - 프롬프트 Frontmatter에 `preview`나 `source` 메타데이터가 명시적으로 기재되어 있는 경우에 한해, 해당 키의 값이 비어있지 않은지 및 실제 이미지 파일이 디스크에 실존하는지 규격 적합성을 확인해야 하며, `python3 scripts/audit_prompts.py` 진단 도구를 구동해 오작동 여부를 지속 확인해야 합니다.
- **이미지 에셋 추가 및 WebP 최적화 규칙**:
  - 프롬프트 예제 또는 본문용 신규 이미지를 `assets/images/<상위메뉴>/<페이지명>/`에 추가할 때에는 반드시 `python3 scripts/optimize_images.py --replace`를 실행하여 고품질 WebP(Quality 85, 최대 1600px)로 일괄 변환하고 원본 대용량 파일을 정리해야 합니다. 마크다운의 `preview:` 및 본문 링크는 항상 `.webp` 확장자를 사용해야 하며, 1MB를 초과하는 바이너리 이미지는 빌드 시 자동 차단됩니다 (`core/build_pipeline.py`, `tests/test_image_assets.py`).
